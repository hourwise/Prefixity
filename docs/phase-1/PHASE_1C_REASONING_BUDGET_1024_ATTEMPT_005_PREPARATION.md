## Handoff root cause and remediation

The live supervisor binary called the generic run_supervised path. That path
passed no workflow handoff to its child. The existing metadata-capable helper
was only exercised by a unit test and was not wired into the real binary.
Consequently, the post-start child received no launch identity, supervisor
PID/path, or child binding metadata.

The remediation wires the real supervisor binary to the registered Attempt 005
identity. It uses one canonical inherited environment JSON value,
PREFIXITY_PHASE1C_WORKFLOW_HANDOFF, containing WorkflowLaunchMetadata:

- launch identity generated by the supervisor from the registered attempt
  identity;
- attempt identity path and canonical SHA-256;
- attempt number and candidate budget;
- supervisor PID and exact executable path;
- child binding mechanism parent_pid and exact child executable path;
- calibration candidate identity;
- Attempt 005 evidence-root identity.

The child does not invent or accept a caller-supplied launch identity. It
validates the serialized metadata against the registered Attempt 005 identity,
then the native classifier verifies supervisor existence/path, child
existence/path, supervisor-to-child parent relationship, exact llama identity,
and exact port-owner PID. Missing, stale, wrong, or mismatched metadata fails
closed.
